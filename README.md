# StudyPlannerApp

برنامه‌ریز مطالعاتی آزمون وکالت/قضاوت - دسکتاپ WPF، دیتابیس محلی SQLite، خروجی اکسل.

## قبل از هر چیز - این کد کامپایل نشده

sandbox من .NET SDK ندارد، پس نتوانستم این پروژه را واقعاً build/run کنم. کد را
با دقت بازبینی کردم (types، using ها، سطح دسترسی API‌های .NET 8/WPF)، ولی تأیید
نهایی با خودت است:

1. پروژه را در **Visual Studio 2026** باز کن (`StudyPlannerApp.sln`).
2. NuGet Restore بزن (خودکار انجام می‌شود یا از منوی راست‌کلیک روی Solution).
3. `StudyPlanner.App` را Startup Project کن و Run بزن.
4. اگر خطای کامپایل گرفتی، متن دقیق خطا را بفرست تا رفعش کنم - حدس نمی‌زنم که درست کار می‌کند.

## ⚠️ قدم اجباری قبل از اولین اجرا: ساخت Migration اولیه

از این نسخه به بعد، به‌جای `EnsureCreated()` از **EF Core Migrations واقعی**
استفاده می‌شود (چون تا الان چند بار مجبور شدی دیتابیس رو دستی پاک کنی - این
مشکل رو برای همیشه حل می‌کنه). قبل از اولین اجرا، یک‌بار در **Package Manager
Console** ویژوال استودیو (با انتخاب `StudyPlanner.Data` به‌عنوان Default project)
این دستور رو بزن:

```
Add-Migration InitialCreate -Project StudyPlanner.Data -StartupProject StudyPlanner.App
Update-Database -Project StudyPlanner.Data -StartupProject StudyPlanner.App
```

یا اگر از CLI استفاده می‌کنی:

```
dotnet ef migrations add InitialCreate --project src/StudyPlanner.Data --startup-project src/StudyPlanner.App
dotnet ef database update --project src/StudyPlanner.Data --startup-project src/StudyPlanner.App
```

اگر دیتابیس قدیمی از نسخه‌های قبل (با `EnsureCreated`) هنوز داری، حتماً قبل از
این کار پاکش کن: `%AppData%\StudyPlannerApp\studyplanner.db` — چون Migration
با یک دیتابیس که Migration History نداره تداخل پیدا می‌کنه.

از این به بعد، هر بار مدل عوض بشه، فقط کافیه دوباره `Add-Migration <Name>` بزنی
و داده‌های موجودت دست‌نخورده می‌مونه.

## امکانات جدید این نسخه

- **تأیید حذف**: کلیک روی ✕ (یا کلید Delete با انتخاب یک ردیف) قبل از حذف واقعی
  یک پیام تأیید نشون می‌ده.
- **پشتیبان‌گیری / بازیابی**: دو دکمه در نوار پایین. Backup یک کپی از فایل `.db`
  می‌سازه؛ Restore فایل پشتیبان رو جایگزین می‌کنه و برنامه رو می‌بنده (باید
  دوباره بازش کنی).
- **اعتبارسنجی ساده**: اگه ساعت پایان قبل از ساعت شروع باشه، یک Toast هشدار
  می‌ده (بدون جلوگیری از ذخیره - چون قفل‌کردن ادیت وسط کار توی DataGrid تجربه‌ی
  بدی می‌سازه).
- **جست‌وجوی سراسری** (تب «جست‌وجو»): جست‌وجو در متن مبحث/توضیحات/عنوان درس، در
  همه‌ی روزها. دابل‌کلیک روی نتیجه می‌بره همون روز و تب مبحث.
- **تب «آمار پیشرفت»**: مجموع دقیقه‌های مطالعه، تفکیک بر اساس درس (نمودار
  میله‌ای ساده)، و توزیع سطح تسلط.
- **یادآوری مرور امروز**: یک بنر طلایی بالای صفحه، اگه امروز مرور اول/دوم/سوم
  هر جلسه‌ای برسه.
- **Toast** به‌جای MessageBox برای پیام‌های سبک (نه خطاهای جدی).
- **فونت Vazirmatn** به‌صورت Embedded (دیگه به فونت نصب‌شده روی سیستم کاربر
  وابسته نیست).
- **آیکون اختصاصی** (`app.ico`) - یک ترازوی طلایی روی زمینه‌ی سرمه‌ای، تولیدشده
  با کد (نه دانلودی)، برای exe نهایی.

## این نوبت اضافه شد

- **کپی مباحث از روز قبل**: دکمه‌ی «کپی مباحث از روز قبل» نزدیک‌ترین روز قبلی که
  مبحث داره رو پیدا می‌کنه و عنوان درس/ساعت/اولویت/سطح تسلط رو کپی می‌کنه -
  متن مبحث و توضیحات طبق تصمیم اولیه همیشه خالی شروع می‌شن.
- **متادیتای اسمبلی** (نام، نسخه، توضیحات) به `StudyPlanner.App.csproj` اضافه شد.
- **اسکریپت `publish.bat`** در ریشه‌ی پروژه - یک exe مستقل و تک‌فایلی می‌سازه
  که نیاز به نصب .NET Runtime روی سیستم مقصد نداره.

## چیزهایی که هنوز عمداً نساختم

- **PDF Export**: نیاز به یک کتابخونه‌ی جدید (مثل QuestPDF) داره که وزن و
  پیچیدگی قابل‌توجهی به پروژه اضافه می‌کنه؛ فعلاً اکسل رو کافی در نظر گرفتم.
  بگو اگه واقعاً لازمش داری.

## تغییرات این نسخه (طبق ۶ درخواست اصلاحی)

1. **تم لاکچری**: پالت سرمه‌ای/طلایی/نقره‌ای/کرم به‌صورت مرکزی در `App.xaml`
   تعریف شده (Style ها برای Button، DataGrid، TabItem، Expander و...) - همه‌جای
   برنامه از همین‌ها استفاده می‌کنند.
2. **تقویم در تب مجزا**: به‌جای `Expander` بالای صفحه، حالا اولین تب از یک
   `TabControl` است و کل صفحه رو در اختیار داره (بزرگ‌تر، بدون تنگی جا).
3. **مبحث و جلسه در تب‌های جدا**: دو تب مجزای «مبحث مطالعه» و «جلسات مطالعاتی».
4. **جابجایی ساعت شروع/پایان و زمان مطالعه** - طبق تصمیمی که چون خودت گفتی
   «هرچی نزدیک‌تره» گرفتم: `StartTime`/`EndTime` به `StudyTopic` منتقل شد،
   و «زمان مطالعه» در همون جدول از تفاضل این دو **خودکار محاسبه می‌شود**
   (`AllocatedMinutes` حالا `private set` دارد، دستی قابل ویرایش نیست).
   جدول جلسات مستقل مانده و ساعت شروع/پایان خودش را برای زمان‌بندی جلسه دارد.
   یک کنترل ساعت سفارشی (`PersianTimePickerControl`) هم ساختم که به‌جای تایپ
   دستی، ساعت/دقیقه از یک لیست کلیک می‌شود.
5. **رفع قطعی باگ تاریخ میلادی**: `DatePicker` بومی WPF با `Language="fa-IR"`
   واقعاً تقویمش را به شمسی تغییر نمی‌دهد (فرض قبلی من غلط بود - عکس خودت این
   را ثابت کرد). به‌جایش `PersianDatePickerButton` ساختم: یک دکمه که همون
   `PersianCalendarControl` خودمون را در Popup باز می‌کند - قطعاً شمسی، چون
   از تقویم خودمان استفاده می‌کند نه از تقویم سیستمی.
6. **صفحه‌ی ورود حذف شد.** چون بعد از لاگین برنامه بی‌صدا بسته می‌شد و مشکل با
   افزودن مکانیزم گزارش خطا هم حل نشد، به‌جای گیر دادن به دیباگ حدسی، طبق
   درخواستت کاملاً حذفش کردم. برنامه مستقیم با `MainWindow` بالا می‌آید.
   `DispatcherUnhandledException` هندلر و try/catch دور راه‌اندازی همچنان در
   `App.xaml.cs` باقی مانده - اگر باز هم خطایی رخ دهد (این‌بار مستقل از لاگین)
   با یک پیام‌باکس دقیق نشانت می‌دهد، نه با بسته‌شدن بی‌صدا.

├── src/
│   ├── StudyPlanner.Core/       مدل‌ها و اینترفیس‌ها - بدون وابستگی به NuGet

## نکات فنی مهم

- **دیتابیس**: `%AppData%\StudyPlannerApp\studyplanner.db` - در اولین اجرا با
  `EnsureCreated()` ساخته می‌شود. طبق مشخصات، اگر مدل بعداً تغییر کند باید به EF Core
  Migrations واقعی سوییچ شود؛ فعلاً برای شروع کار همین کافی است.
- **ComboBox در DataGrid**: چون `DataGridComboBoxColumn` عضو Visual Tree نیست،
  `ItemsSource` هرکدام با `ElementName=RootWindow` و مسیر `DataContext.XxxOptions`
  بایند شده - دقیقاً همان راه‌حلی که در بریف خواسته بودی.
- **مرور خودکار جلسات**: `StudySession` سه فیلد `ReviewDate1/2/3` را از `Date`
  محاسبه می‌کند و `INotifyPropertyChanged` را روی تغییر `Date` هم برای خودش هم برای
  سه فیلد مرور Raise می‌کند - در UI بدون ذخیره/رفرش آپدیت می‌شوند. این سه فیلد در
  دیتابیس `Ignore` شده‌اند (ستون واقعی ندارند).
- **ذخیره‌ی تغییرات سلولی**: چون ویرایش مستقیم در DataGrid رخ می‌دهد، `CellEditEnding`
  در `MainWindow.xaml.cs` تغییرات را به دیتابیس commit می‌کند. `DatePicker` داخل ستون
  جلسات هم چون خارج از چرخه‌ی عادی edit سلول عمل می‌کند، هندلر جدا دارد
  (`SelectedDateChanged`).
- **خروجی اکسل**: `ExcelExportService` همیشه یک فایل تازه می‌سازد (`XLWorkbook` جدید)
  و هیچ فایل موجودی را باز/ویرایش نمی‌کند. تاریخ شمسی روز در سلول B2، جدول مباحث از
  ستون A، جدول جلسات از ستون J.

## چیزهایی که تصمیم گرفتم بدون پرسیدن ازت

- **RowNumber**: بعد از هر افزودن/حذف مبحث، `RenumberTopicsAsync` در Repository
  همه‌ی ردیف‌های همان روز را بر اساس `Id` (ترتیب افزودن) دوباره شماره‌گذاری می‌کند.
- **کپی مباحث از روز قبل** (بند ۴.۲ بریف تیم، «اختیاری»): **پیاده نشده.** در بریف
  به‌عنوان قابلیت اختیاری ذکر شده بود، نه الزامی؛ اگر لازمش داری بگو تا اضافه کنم -
  خودم تصمیم نگرفتم که مهم نیست، فقط اولویت‌بندی کردم.
- استایل بصری UI ساده و کاربردی نگه داشته شده (نه تم navy/gold که در نسخه‌ی قبلی
  کار کرده بودیم) چون این بریف چیزی درباره‌ی ظاهر نگفته بود. اگر خواستی همون تم رو
  اینجا هم پیاده کنم بگو.

## موارد باز که تیم شما هنوز تصمیم نگرفته (از بریف خودتان، بند ۷)

این‌ها را عمداً پیاده نکردم چون در بریف «برای بحث» علامت خورده بودند، نه تصمیم‌شده:

- احراز هویت/چندکاربره بودن
- یادآوری/نوتیفیکیشن برای تاریخ‌های مرور
- قالب‌بندی رنگی در خروجی اکسل بر اساس اولویت/سطح تسلط
- EF Core Migrations واقعی به‌جای `EnsureCreated()`

اگر این‌ها را تصمیم گرفتید، بگو تا اضافه کنم.
